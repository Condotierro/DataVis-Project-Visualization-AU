Overall, there are no constraints or restrictions on which visualization tool or library you choose. In the past, students have successfully passed the course using tools like [plotly](https://plotly.com), [R-shiny](https://shiny.posit.co), [D3.js](https://d3js.org), or even [Microsoft PowerBI](https://www.microsoft.com/en-us/power-platform/products/power-bi) for their course projects. Regardless of which one you choose, it is recommended that you use a visualization library or tool that does not have a huge technical overhead and lets you make design iterations quickly - yet, it needs to allow for interactivity. Static charts as MS Excel produces them will not be enough to pass the course.

In case you are still undecided in this regard, there are a number of directions in which you might want to look. You may want to do a quick Hello-World example in each (e.g., a simple scatterplot or line chart) just to get a feel for the different libraries and tools.

### 1. Language agnostic:

If you are not really fluent in any programming language, or you often switch between languages or work in a team that uses multiple programming languages, then a declarative visualization grammar is for you. In a declarative visualization grammar, you just specify what you want to see and let the framework figure out the how. For an overview of different grammars and their use, the following two articles are recommended: [doi:10.1109/TVCG.2022.3209460](https://doi.org/10.1109/TVCG.2022.3209460) and [doi:10.1145/3544548.3580837](https://doi.org/10.1145/3544548.3580837) In case you just want to get started, we advise to use either [Vega-Lite](https://vega.github.io/vega-lite/) or its bigger and mightier brother [Vega](https://vega.github.io/vega/) as a visualization grammar of choice. For Vega-Lite, we offer a video tutorial here: [https://vis-au.github.io/vl/](https://vis-au.github.io/vl/) While being language agnostic grammars, Vega and Vega-Lite offer several language bindings for experienced coders - e.g., [Altair](https://altair-viz.github.io) for Python and the [Vega-Lite API](https://vega.github.io/vega-lite-api/) for JavaScript, both of which are highly recommended. Tutorials for both can be found at [https://altair-viz.github.io/altair-tutorial/README.html](https://altair-viz.github.io/altair-tutorial/README.html) (for Altair) and at [https://www.classcentral.com/course/youtube-learning-vega-lite-api-for-javascript-on-observable-93383](https://www.classcentral.com/course/youtube-learning-vega-lite-api-for-javascript-on-observable-93383) (for the Vega-Lite API).

### 2. JavaScript/TypeScript:

The "industry-standard" for web-based visualization is certainly the [D3.js library](https://d3js.org). D3 stands for "Data-Driven Documents" and has been around for over a decade now. You can find the initial publication from 2011 here: [doi:10.1109/TVCG.2011.185](https://doi.org/10.1109/TVCG.2011.185) If you are experienced with web-based programming, this library is for you. If you want to learn D3, I've had good experiences teaching D3 with the book ["D3 for the Impatient" (OReilly, 2019)](https://www.oreilly.com/library/view/d3-for-the/9781492046783/). While it is certainly a bit outdated by now, it still does a great job of teaching the fundamentals - even if some of the function calls have meanwhile changed. You can also find plenty of tutorials online - like [D3 in Depth](https://www.d3indepth.com) or [Learn D3](https://observablehq.com/@d3/learn-d3).

### 3. Python:

There are plenty of choices for creating visualizations in Python available. The library we recommend is [Bokeh](https://bokeh.org). It allows for a reasonable functionality and flexibility, while still being not too verbose and too technical to handle. From experience with various student projects, it is more lightweight and user-friendly than many of its contenders like [Seaborn](https://seaborn.pydata.org) or [Matplotlib](https://matplotlib.org). Note that if you want extreme scalability or custom interactivity that may not generalize to all plots, there are also tailored libraries for specific plot types, like [Jupyter Scatter](https://jupyter-scatter.dev/) for generating scatterplots or [libraries for Up-Set plots](https://upset.app/implementations/#python-libraries) - i.e., visualization of set-based data.

### 4. No-code Solutions:

If you are not big on coding, as som eof you aren't Computer Science students, you should look into some of the available no-code and low-code solutions. These include [Tableau Public](https://public.tableau.com/) and [KNIME](https://www.knime.com), with Tableau being more focused on the visualization side and KNIME being a bit stronger on the data mining and data preparation side of things. You can find some introductions to Tableau [here](https://public.tableau.com/app/learn/how-to-videos) and to KNIME [here](https://www.knime.com/getting-started-guide). There are other no-code solutions out there, with which you may want to experiment - albeit they do not offer creating intercative charts or the interaction is very limited, so they aren't helpful for the course project, but may still be good starting points to prototype and try out different chart types before deciding to implement them in another tool. If you want to have a look, good pointers are [RAWGraphs](https://www.rawgraphs.io) and [DataWrapper](https://www.datawrapper.de). If you find any other good tools or websites, let me know so that I can add them to this list!
